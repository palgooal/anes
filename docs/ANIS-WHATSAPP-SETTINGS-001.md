## 2. الهدف والنطاق

### 2.1 الهدف

توثيق متطلبات إدارة إعدادات WhatsApp Cloud API من لوحة المدير في نظام أنيس، بما يشمل تخزين الإعدادات وحماية الأسرار، والفصل بين بيئتي الاختبار والإنتاج، والتفعيل الآمن، ومعالجة فشل الإرسال، وسجلات الإرسال والتسليم والتدقيق، تمهيدًا للتنفيذ المرحلي بعد اعتماد الوثيقة.

### 2.2 ضمن النطاق

- جدول إعدادات مخصص `whatsapp_settings` وخدمة قراءة موحدة مع الرجوع إلى إعدادات Laravel الحالية.
- إدارة Access Token وأسرار Meta الأخرى بصورة مشفرة، ومتابعة صلاحية الرمز.
- أوضاع الإرسال، والفصل بين بيئتي الاختبار والإنتاج، وتفعيل الإنتاج بعد التحقق من الجاهزية.
- سياسة الفشل الآمن لرموز OTP المرسلة عبر WhatsApp.
- اختبار الاتصال والإرسال من لوحة المدير ومن سطر الأوامر دون كشف الرموز.
- سجل حالات الرسائل، وسجل تدقيق الإعدادات.
- Webhook حالات تسليم الرسائل مع التحقق من توقيع Meta.
- صلاحية مستقلة `manage-whatsapp`.

### 2.3 خارج النطاق

- أي تغيير في آلية المصادقة أو قراراتها (ANIS-AUTH-OTP-001)، ومنها طول الرمز وصلاحيته وحدود الإرسال والأجهزة الموثوقة.
- أي تغيير في رحلة الحجز أو قراراتها (ANIS-BOOKING-JOURNEY-001)، ومنها رموز التحقق أثناء الحجز.
- قنوات إرسال أخرى، ومنها SMS (مؤجل بقرار CNF-AUTH-01).
- استقبال رسائل المستخدمين الواردة عبر WhatsApp أو الرد عليها.
- إدارة قوالب Meta أو إنشاؤها من النظام.
- رقم روابط `wa.me` العامة (`services.whatsapp.number`) ونشرها، المحكوم بـ REQ-AUTH-37.
- سجل الأحداث الأمنية العام (DEC-AUTH-008)، الذي يبقى قرارًا مستقلًا معلّقًا.
- الحد اليومي لرموز تسجيل الدخول لكل رقم (GAP-AUTH-05)، الذي يبقى ضمن وثيقة المصادقة.

## 4. القرارات المعتمدة

### DEC-WA-001 — جدول الإعدادات والرجوع إلى إعدادات Laravel

- جدول مخصص `whatsapp_settings` يحفظ إعدادات WhatsApp.
- Access Token يُخزَّن مشفرًا.
- يُرجع إلى إعدادات Laravel الحالية (`config/services.php` و`.env`) **عند عدم وجود سجل إعدادات، أو ما دام السجل «قيد التحضير» ولم يُفعَّل مصدر قاعدة البيانات** (تعديل 0.1.7، القرار D1: نقل الإدارة على مرحلتين).
- لا يتحول مصدر رموز OTP إلى قاعدة البيانات بإنشاء السجل ولا بتعديله، بل بإجراء تفعيل صريح فقط (REQ-WA-66).

**الحالة:** معتمد.

### DEC-WA-002 — الفصل بين بيئتي الاختبار والإنتاج

- إعدادات منفصلة لكل من بيئة الاختبار وبيئة الإنتاج.
- تفعيل الإنتاج بإجراء إداري صريح بعد التحقق من الجاهزية.

**الحالة:** معتمد.

### DEC-WA-003 — الفشل الآمن لرموز OTP

- يُبطَل رمز OTP عند فشل إرساله أو عند عدم التأكد من نتيجة الإرسال.
- يُسمح بطلب رمز جديد وفق الضوابط المعتمدة في ANIS-AUTH-OTP-001.
- لا يُكشف الرمز، ولا تُغيَّر قناة الإرسال.

**الحالة:** معتمد.

### DEC-WA-004 — الإدارة من لوحة المدير وصلاحية مستقلة

- إدارة إعدادات WhatsApp API من لوحة المدير.
- صلاحية مستقلة `manage-whatsapp`، تُمنح حاليًا لدور `Admin`.

**الحالة:** معتمد.

### DEC-WA-005 — سجل التدقيق وسجل حالات الرسائل

- سجل تدقيق لتغييرات الإعدادات.
- سجل لحالات الرسائل المرسلة.
- لا يكشف أي من السجلين رموز OTP أو البيانات السرية.

**الحالة:** معتمد.

### DEC-WA-006 — Webhook حالات التسليم

- يتضمن التنفيذ Webhook لاستقبال حالات تسليم الرسائل من Meta.
- يُتحقق من توقيع Meta **قبل الوثوق بأي بيانات في الطلب**.

**الحالة:** معتمد.

### DEC-WA-007 — مدد الاحتفاظ بالسجلات

- 90 يومًا لسجل حالات الرسائل، وسنة لسجل تدقيق الإعدادات.
- المدتان **مقترحتان ومعلّقتان**، لا نهائيتان، إلى حين اعتماد سياسة الاحتفاظ المناسبة بعد مراجعة المتطلبات النظامية.

**الحالة:** معتمد مع تفاصيل معلّقة (PND-WA-01).

### DEC-WA-008 — تاريخ انتهاء Access Token

- يُعتمد تاريخ انتهاء الرمز الفعلي عند توفره، ولا تُفترض مدة صلاحية ثابتة.
- الجاهزية لا تُثبت بـ `debug_token` وحده.

**الحالة:** معتمد.

### DEC-WA-009 — حدود النطاق

- لا يغيّر هذا العمل نطاق المصادقة أو الحجوزات أو القرارات السابقة في الوثيقتين المرتبطتين.
- لا تُضاف وظائف خارج تكامل WhatsApp المعتمد.
- يُحافظ على توافق الوظائف والاختبارات الحالية ما أمكن.

**الحالة:** معتمد.

| البيئة (Environment) | مجموعة إعدادات مستقلة: `test` (بيئة الاختبار، مثل رقم Meta التجريبي) أو `production` (الرقم الرسمي المعتمد) |
| الوضع (Mode) | حالة الإرسال الفعالة: `disabled` (لا إرسال)، `log` (كتابة في السجل دون إرسال، للتطوير فقط)، `test` (الإرسال عبر بيئة الاختبار)، `production` (الإرسال عبر بيئة الإنتاج) |
| مصدر الإعدادات | `database` عند وجود سجل في `whatsapp_settings` فُعِّل مصدرُه، أو `env` عند غياب السجل أو ما دام «قيد التحضير» |
| قيد التحضير | حالة سجل الإعدادات بعد نقل الإدارة وقبل التفعيل: تُعدّ فيه البيئتان وتُختبران، ويبقى `.env` مصدر إرسال OTP. الحالة مستقلة عن الوضع |
| التفعيل | إجراء صريح يحوّل مصدر OTP من `.env` إلى قاعدة البيانات ويحدد الوضع النافذ في كتابة واحدة ذرية (REQ-WA-66) |
| الاستعادة إلى `.env` | إعادة مصدر OTP إلى `.env` من الخادم، مع إبقاء السجل وأسراره ووضعه دون تغيير، فيعود السجل «قيد التحضير» (REQ-WA-70) |
| بصمة الإعدادات | قيمة HMAC-SHA256 بمفتاح التطبيق تُحسب من إعدادات بيئة الإنتاج المؤثرة في الإرسال، ولا يمكن استرجاع أي قيمة منها (REQ-WA-68) |
| نتيجة الطلب (`send_status`) | نتيجة طلب الإرسال إلى Meta: `accepted` (رد 2xx مع `wamid`)، `rejected` (رد 4xx)، `uncertain` (انتهاء المهلة أو انقطاع الاتصال أو رد 5xx)، `blocked` (الإرسال معطّل أو البيئة غير جاهزة) |
| حالة التسليم (`delivery_status`) | الحالة الفعلية الواردة من Webhook: `sent` أو `delivered` أو `read` أو `failed` |
| قبول Meta | رد 2xx يتضمن `wamid`. **لا يعني وصول الرسالة.** |
| الرمز المبطل | رمز OTP لا يُقبل في التحقق بسبب فشل إرساله أو عدم التأكد منه |
| رمز اختبار المدير | رمز يُرسل لغرض اختبار القالب والوصول فقط، ولا علاقة له برموز تسجيل الدخول |
| الجاهزية | استيفاء كل شروط REQ-WA-24 لبيئة الإنتاج |
